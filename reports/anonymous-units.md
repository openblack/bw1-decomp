This is evidence only. I edited nothing in `config/`, `src/` or `include/`.
Every address below is BW1W120. "Mac" means BW1M119 `config/BW1M119/symbols.txt`.
You can reproduce any row with `python tools/unit-evidence.py <lo-hi> ... --mac`.

## How the boundaries were established

* **Unit end.** MSVC6 emits the `crt_xc_fn_ctypeGuard_*` + `crt_xc_fn_atexitCleanupReg_*` pair last in every
  object that includes the locale headers. It is a template static: it sets guard byte `0xfac934` and registers
  an atexit callback for `0x407870`. The pair is 0x30 bytes including padding, and the unit ends right after it.
* **Unit start.** Header statics (`secsPerYear`, `sentinelNegOne`, `piOverTwo`, …) put their initializer thunks
  at the very top of an object. A static object defined mid-file also gets an initializer at its definition
  (PSysExplosion `0x680690`, PSys3d `0x6722c0`/`0x672a70`, PSysLightning `0x692eb0`/`0x6936f0`). An initializer
  with no guard just before it therefore does **not** prove a boundary.
* **.bss order.** Within one object, statics are laid out in reverse declaration order (first declared = highest
  address). Objects follow link order. A later range whose statics sit *below* the previous range's statics
  is the same object.
* **Mac order.** CodeWarrior places a unit's functions in **reverse** source order (weak/inline copies at the
  top), then `.__sinit_<file>_cpp`. If Windows code X follows unit A and X is part of A, then on Mac X sits
  *below* A's functions. If it sits above them, X is a separate Mac unit.
* **configure.py names.** The 327 `configure.py` entries with no split are one-line skeletons (`#include "X.h"`)
  added in 2d2b4589 for known headers. No `X.cpp` string backs any of them in any binary. So a fitting skeleton
  name shows that a header of that name exists, not that the `.cpp` existed.
* **Slot rule.** The game objects link in case-insensitive alphabetical order. I found only three exceptions:
  GJPersistent after GJUtils, TerrainMapInfo after TerrainMaterialInfo, and ChallengeRoom after WorshipTotem.
  An unknown name must therefore sort strictly between its neighbours, and `.` sorts before letters.
